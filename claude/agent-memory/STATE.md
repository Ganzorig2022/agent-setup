## Lessons Learned
- `~/.claude/rules/*.md` auto-loads into EVERY session globally; `paths:` frontmatter is ignored at user level (CC bugs #16299/#21858). Keep project-specific context in project CLAUDE.md imports, not user-level rules.
- CLAUDE.md + always-on rules are the main per-turn token cost — keep them lean; push detail into skills/agents (lazy-loaded).
- Custom subagents load ~/.claude/CLAUDE.md and its `@imports` (the built-in Explore/Plan agents skip it). Share content into all agents via a file `@import`'d from CLAUDE.md, not per-agent copies — e.g. the deduped Prompt Defense baseline now lives once at ~/.claude/prompt-defense.md.
- STATE.md is a static `@import`, NOT Claude Code's subagent persistent-memory feature (that needs `memory: user|project|local` frontmatter and lives at ~/.claude/agent-memory/<agent>/MEMORY.md). Nothing auto-writes STATE.md — capture learnings with `/retro`.
- Agent `model:` frontmatter IS honored: `sonnet|opus|haiku|fable|inherit|<full-id>` (defaults to `inherit`).
- settings.json hook commands run via shell — write `$HOME/...`, never a hardcoded home path. Hardcoded /Users/dev silently disabled ALL hooks on the Fedora box (no error; hooks just never fire). Hooks load at session start — path fixes need a new session.
- Hook mechanics: output channels — top-level `systemMessage` = user-facing non-blocking; `hookSpecificOutput.additionalContext` = injected for Claude's next request; `decision:"block"`+`reason` (or exit 2) = blocks & feeds Claude. Stop fires every turn-end (no true session-end event) — throttle via marker file; `stop_hook_active` guards recursion. PostToolUse can match a specific tool name (`ExitPlanMode` = fires on plan approval — the "plan is done" interception point); hooks CANNOT add choices to the native plan-approval menu.
- Headless `claude -p` (and `--agent`) inherits `permissions.defaultMode` — with global "plan", agents write findings to a plan FILE and stdout gets only a handoff line (looks like the agent found nothing). ALWAYS pass `--permission-mode default` in automation; also retry transient "API Error: ConnectionRefused" outputs in long sequential runs.
- SubagentStop payload: use `agent_transcript_path` (`transcript_path` = the MAIN session — docs are wrong); the hook can fire before the agent transcript flushes (poll ~3s). `subagentStatusLine` stdin = `{tasks:[{id=agentId, description, tokenCount(live), status}]}` per refresh, output `{"id","content"}` JSON lines; model NOT in payload — read it from the agent transcript.
- Browser-automation gotchas (chrome-devtools-axi persistent profile + npx-by-absolute-path under launchd, X.com read/write mechanics, Draft.js composer traps, Bluesky RSS as the token-free proxy) live in the `chrome-devtools-axi` skill — load it before any X or headless-browser work.
- Telegram Bot API = free unattended push channel for local automations: @BotFather bot creation is free (no billing/card); the user must message the bot ONCE before it can DM them (grab `chat_id` from `getUpdates`); `token`+`chat_id` in env; `sendMessage` caps at 4096 chars so chunk long messages.
- The auto-mode classifier blocks Claude from editing `.claude/settings*.json` permissions, from `mv`/`rm` of pre-existing repos, from `cp -R` that creates a new directory inside a repo, from installing plugins from external repos, and from looping login attempts across many accounts (credential-stuffing shape, even against the user's own API) — even with in-chat user approval. Don't retry; hand the exact command to the user to run via the `!` prefix. Same handling for the user's own `~/.claude/hooks/block-dangerous.sh` PreToolUse hook, which blocks `rm -rf` outright ("recursive force delete is not allowed. Do it manually if intentional") — hand it over, never route around it.
- Demo/seed account credentials **drift in production** — verify with a real API login immediately before publishing them anywhere (App Store demo account, tester handouts, docs). A stale one cost a **Guideline 2.1 rejection** and a month of review round-trips. A generic `INVALID_CREDENTIALS` response cannot distinguish "no such user" from "password changed", and the ways to find out (password-reset, register probe) have real side effects — don't.
- User's daily terminal is cmux (com.cmuxterm.app) — a plain terminal emulator, so tmux runs fine inside its panes; only sessions needing phone-mirror must live in tmux. Phone is a Xiaomi (MIUI) — exclude Tailscale from battery optimization or it gets killed in background.
- launchd python jobs CANNOT read or write `~/Desktop` subtrees created from a terminal context — per-file `com.apple.macl` TCC ACLs make globs silently return empty and writes fail `Errno 1` — and the failure is silent enough to blind a script's own idempotency checks. Keep automation output in `~/<dir>` and symlink onto Desktop for visibility. Related: lid closed with `SleepDisabled=1` keeps the Mac running but Wi-Fi is often down at launchd fire time; calendar jobs are never lost to sleep (they fire once at next wake, lost only on shutdown) — gate network stages with long retries, don't trust the scheduled slot.
- Boolean quality gates render "no evidence" as a verdict — a rate over zero samples reads as *failed*, and a gate met by one source class reads as *passed*. Use `passed`/`failed`/`insufficient_evidence` with a per-class minimum-sample threshold, and persist the counts next to the state.
- Scanned/image PDFs: the Read tool fails with "pdftoppm is not installed" and `pdftotext` is also absent on this Mac. Render with the built-in `qlmanage -t -s 2400 -o <dir> file.pdf` then Read the resulting PNG — no install needed. A PDF containing `/Image` and no `/Font` has no text layer at all, so stream/zlib extraction returns zero characters; go straight to rendering.
- Two browser tools, different anchors: **Claude-in-Chrome MCP** acts inside the Chrome profile bound to the *session's* account — can be a different Google login than the user's own profile. **computer-use** screenshots the physical display but grants browsers **read tier** (screenshot-only; click/type/scroll blocked) — use the Chrome MCP to interact. Multi-monitor: a window may render split; `switch_display auto` + re-screenshot recovers the main monitor. Meta's Business/Developers console is hostile to automation: token/chip inputs (App domains, redirect URIs, JS SDK allowed domains) need `Return` to commit before Save or the value is silently dropped on reload; buttons often need a second click; always verify a save by reloading, never by absence of an error.
